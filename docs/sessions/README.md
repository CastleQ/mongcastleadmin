# 작업 세션 기록

한 덩어리의 작업이 끝날 때마다 여기에 **무엇을 왜 그렇게 했는지** 남긴다.
커밋 메시지는 "이 변경이 무엇인가"를 적고, 이 기록은 **"그날 전체의 흐름과 판단"** 을 적는다.

## 파일 이름

`session-YYYY-MM-DD.md` — 하루에 여러 번이면 `session-YYYY-MM-DD-2.md`, `-3`.
한 대화가 여러 날에 걸쳐 있으면 **끝난 날짜**로 짓고, 안에 기간을 적는다.

## 누가 읽나

- **사장님**: 가끔 열어 "그때 왜 그렇게 정했더라"를 확인한다 → 쉬운 말로, 용어는 풀어서
- **다음 AI**: 새 세션을 시작할 때 최근 한두 개를 읽어 흐름을 따라잡는다 → 사실·경로·명령을 정확히

## 틀

```md
# 작업 세션 기록 — YYYY-MM-DD (한 줄 제목)

기간 / 작업 가지 / 배포 여부를 머리에 적는다.

## 한 일
| 커밋 | 내용 |
|---|---|

## 결정한 것 (왜 그렇게 정했나)
- 결정 — 이유. 누가 정했는지(사장님/AI 판단)를 밝힌다

## 새로 알게 된 것 · 함정
- 다음에 또 당할 만한 것. 규칙으로 굳힐 만하면 CLAUDE.md 나 스킬로 옮기고 여기 "옮김"이라 적는다

## 내가 틀린 것
- 숨기지 않는다. 무엇을 잘못 알았고 어떻게 바로잡았는지

## 확인 못 한 것 · 남은 일
```

## 규칙

- **숨기지 않는다.** 실수·되돌린 것·판단으로 채운 값을 그대로 적는다. 나중에 원인을 찾을 때 그게 제일 쓸모 있다
- 같은 내용을 두 곳에 적지 않는다. 규칙으로 굳은 것은 CLAUDE.md·스킬로 옮기고 여기엔 "옮김"만 남긴다
- 사장님이 정한 업무 규칙은 `docs/운영규칙.md` 로 옮긴다
